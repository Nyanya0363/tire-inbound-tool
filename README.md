# 轮胎入库匹配工具

把厂家进库 Excel 自动转换成系统导入模板。当前供应商为 **四川海大轮胎橡胶集团股份有限公司**，支持海大、天府、迈劲在同一文件中匹配并统一导出供应商，商品保留各自品牌和编号。

所有 Excel 都在浏览器本地解析和匹配，不会上传到服务器。

## 本地运行

```bash
npm install
npm run dev
```

打开 Vite 输出的地址即可。

## 当前流程

1. 选择供应商“四川海大轮胎橡胶集团股份有限公司”（支持海大、天府、迈劲）
2. 上传**本日需要入库**的厂家文件（支持 `.xlsx` / `.xls` / `.csv`）
3. 页面自动识别表头；识别错了可以手动改列
4. 点击“开始匹配”
5. 核对结果：可导入 / 需确认 / 不可导入
6. 下载导入模板 `.xlsx` 或 `.xls`

发现疑似新品时，可点该行“标记待新建”。已有且已确认的商品可以继续导出；待新建行不会进入入库模板，导出确认会列出提醒，并提供单独的“待新建商品清单”（包含厂家型号、品牌、数量、单价及新建说明）。回业务系统建好商品、更新目录后再重新匹配这些行。所有未解决行都需明确选择对应商品、待新建或本次跳过，才能导出。导出弹窗分别列出待新建和主动跳过明细。

结果页会显示：

- 三类状态：可导入、需确认、不可导入
- 合计核对：源文件行数/数量/金额、可导入合计、未导入差异
- “需确认”行可以查看型号差异对比
- 可批量确认相同差异，例如“商品资料缺少 XL”
- 导出前确认弹窗：导出行数、跳过行数、数量、金额、单价口径
- 最近处理记录：文件名、时间、匹配数量、导出格式

更改型号、数量、单价、单位或品牌列后，旧匹配结果立即清空，必须重新匹配；更换商品目录也会使结果失效。

数量须为正整数、单价须大于 0。空白、非法数字、负数和零值会逐行显示错误并阻止该行导入；请修正原表后重新上传，或明确本次跳过。异常行的合计仅包含可计算数值，不是完整订单合计。

单价口径可以直接选“底价”或“价格”，不需要从全部列名里找。字段映射默认折叠，只有自动识别错误时才需要展开调整。供应商名称由所选供应商配置固定。品牌列支持海大/HAIDA、天府/TIANFU、迈劲/MILEKING；未填品牌时从型号识别，无法判断则默认海大。处理完成后可以点“重新开始”处理下一单，导出记录会保存在“最近处理记录”里。

上传前只保留**一行表头 + 本日需要入库的商品行**，删除合计行、备注行、其他日期区块和不属于当前供应商配置的品牌数据。海大、天府、迈劲无需拆分文件。
标准表头是：

```text
序号 | 品牌 | 规格 | 单位 | 价格 | 数量 | 金额 | 当期 | 规模 | 促销 | 现金 | 底价 | 付款
```

页面提供“下载空白表头”和“下载示例文件”。

当前工具按“干净文件”设计，不做复杂清洗。上传后会做预检：

- 检测到多个日期区块 → 拦截，要求只保留本日区块
- 检测到未配置品牌（当前支持海大、天府、迈劲）→ 拦截，要求先删除其他品牌行
- 合计行、重复表头等无法识别的行会提示并忽略

如果文件有多个工作表，当前只读取第一个工作表。

导入模板的列固定为：

```text
供应商 | 商品编号 | 商品名称 | 规格 | 单位 | 数量 | 单价
```

## 商品目录

商品目录是一份合并后的 JSON：`public/catalog.json`。

只保留匹配需要的字段：

```json
{
  "code": "HD517-165R14LT",
  "name": "轮胎（海大）",
  "spec": "165R14LT8PR HD517 96/95Q",
  "brand": "海大",
  "unit": "件",
  "barcode": "51716514517"
}
```

不包含库存、成本价、批发价、仓库位置等敏感字段。

更新商品资料有两种方式：

**方式一：页面内生成**

打开页面底部的“维护商品目录”，上传新的商品资料 Excel，点击“下载 catalog.json”，然后替换项目里的 `public/catalog.json` 并提交。

上传后会先显示和当前目录的对比：

- 新增商品数
- 删除商品数
- 规格变化数
- 重复商品编号
- 各品牌商品数量

如果会删除商品，需要勾选确认后才能下载。也可以点“在当前页面临时应用”直接试用新目录。

**方式二：命令行生成**

```bash
npm run catalog
```

默认读取根目录的 `商品资料.xlsx`，也可以指定文件：

```bash
npm run catalog -- "新的商品资料.xlsx"
```

然后把 `public/catalog.json` 一起提交。

## 匹配逻辑

供应商配置限定可处理的品牌。厂家型号和商品规格使用同一套解析规则，拆分为：

```text
品牌 | 花纹 | 规格 | 层级 | 载重速度 | 标识
```

例如：

```text
HAIDA 165R14LT 8PR 96/95Q HD517
=> 海大 | HD517 | 165R14LT | 8PR | 96/95Q |
```

匹配顺序：

1. 已确认的型号对应关系：型号字段一致或原文一致，并且目标商品规格、品牌、单位快照仍有效，才复用；旧版仅保存 SKU 的记忆需要重新核对。
2. 商品规格为判断依据，SKU 只定位和导出；商品规格缺失的字段不会从 SKU 补齐。可识别的 SKU 型号与规格冲突时，提示人工核对。SKU 花纹只写基础编号而规格附带 EV/EVT/SP 时，视为编号信息较少，不用编号覆盖规格后缀。
3. 严格键唯一命中、识别到完整载重速度且没有未识别内容或目录冲突 → 自动匹配。
4. 同品牌、同花纹、同尺寸、同层级只有描述差异 → 必须确认后导出；确认后保存规格快照。
5. 层级、载重速度、白字或左右方向等关键参数冲突 → 逐项显示差异，需要人工选择，不能批量确认。
6. 基础花纹不同的商品直接排除，人工选择和旧映射也不能绕过。仅 EV 后缀不同、同品牌同尺寸时保留候选，提示可能是同款升级，需人工核对后保存；EVT/SP 不按 EV 升级处理。
7. 没有同花纹同规格候选时提示疑似未建档；同花纹其他尺寸只作为辅助参考。确认新品后回业务系统新建，更新本工具目录后重新匹配。

解析兼容全角字符、字段间空格、乘号写法、紧跟尺寸的 `(16)` / `-18` 层级，以及 RUNSPIRIT、HDA 等花纹；保留 `22.5` 小数轮辋，不把它与 `22` 合并。此类格式规范化不会自动放宽花纹、层级等商品参数。

候选按照规格字段排序，SKU 文本和相似度分数不参与自动确认。未覆盖的花纹/规格会提示规则无法完整识别，保留人工选择入口；人工确认后原文也能记忆。

### 待核对确认

- 核心字段匹配会归入“需确认”
- 进入“需确认”后，会按差异原因再分小类，例如“缺少 XL”“缺少低滚阻”“缺少载重速度”
- 点击小类只会筛选表格，不会直接确认；先核对下方明细，再点“确认本组可批量差异”
- 关键字段不一致的小类只能逐条核对
- “有候选，需手动选择”的小类不会出现批量确认按钮
- 可以逐行确认，也可以按小类确认
- 还有未处理行时，导入模板下载按钮会禁用；候选、无法识别和异常数据行也需明确处理
- “撤销确认并删除记忆”会撤销当前确认，并删除同一型号字段的相关记忆；“清除选择并删除记忆”同理
- 映射管理中删除或导入记忆后，需重新匹配，避免继续使用旧结果
- 结果表格支持筛选：全部 / 需确认 / 可导入 / 不可导入

### 映射记忆管理

页面底部可以：

- 查看已保存的厂家型号 → 商品编号映射
- 删除错误映射
- 导出映射 JSON
- 导入映射 JSON
- 检查商品编号、规格、品牌、单位是否与确认时一致

人工选择商品或确认核心字段差异后会保存型号字段和商品快照；型号顺序、空格变化时可复用。目标商品变化、旧记忆缺少快照或对应关系冲突时，要求重新核对。JSON v2 保留这些快照，兼容导入旧版映射作为待核对候选。记忆仍在当前浏览器本机，请定期导出备份。

### 自动备份到本地 JSON

在“映射记忆管理”点击“选择自动备份文件”，选择固定的 `.json` 文件。支持 File System Access API 的 Chrome / Edge 可在新增、修改、确认映射以及完成匹配或导出时自动更新该文件。页面显示保存状态；写入失败或权限过期会提示恢复授权，浏览器记忆仍保留。

重新打开后会尝试恢复文件位置；需要权限时点击“恢复自动备份”。已有备份会先读取并合并，不会把空浏览器记忆直接覆盖到备份中；同型号记录冲突、供应商不一致或备份格式不正确时停止覆盖，需先导入核对或选择新文件。不支持该 API 的浏览器仍可手动导出 JSON。

当前部署为 GitHub Pages 静态页面，尚未接入 GitHub 自动提交。自动备份不包含 GitHub 凭据，不会向仓库上传数据。项目内 `映射备份/` 目录默认被 Git 忽略。

## 增加新品牌

在 `src/brands/` 下新增一个适配器，例如：

```text
src/brands/xxx/
  adapter.ts
```

实现 `src/brands/types.ts` 里的 `BrandAdapter`：

- `parseInbound`：解析厂家型号
- `parseProduct`：解析商品规格，并检查可识别的 SKU 型号冲突
- 输入列别名、供应商名称、模板文件名等

然后注册到：

```ts
// src/brands/index.ts
export const brandAdapters = [haidaAdapter, xxxAdapter];
```

商品目录不需要拆成多个文件，继续使用同一个 `public/catalog.json`，匹配时按品牌过滤。

建议每个品牌都配一组测试样本，放在 `tests/` 下。

### 添加视频教程

静态网页不能直接保存视频文件。推荐先把视频上传到 B 站、GitHub Release 或云存储，再填写链接。

页面底部有“教程视频管理”：

1. 填写标题、说明、视频地址
2. 选择“自动判断 / 视频文件 / 外部链接”
3. 点击“添加教程”
4. 下载 `tutorials.json`
5. 替换项目里的 `public/tutorials.json` 并提交

如果视频文件放在 `public/tutorials/` 下，地址填 `tutorials/文件名.mp4`；大视频不建议直接放进 GitHub Pages 仓库。

支持：

- `.mp4` / `.webm` / `.ogg` 直接播放
- B 站等外部链接打开观看

## 诊断日志

- 每次上传、匹配、人工选择、导出都会写入本地诊断日志
- 日志包含：行号、原始型号、解析结果、匹配方式、候选、错误堆栈
- 日志只保存在浏览器 `localStorage`，不会上传
- 页面底部可以下载诊断日志 JSON
- 生产构建会注入 Git commit SHA，方便定位是哪一版代码出的问题
- 每次匹配结果也会体现在“匹配报告”Excel 里

## 部署到 GitHub Pages

1. 把项目推到 GitHub 仓库
2. 仓库 Settings → Pages → Source 选择 **GitHub Actions**
3. 推送到 `main` 后，`.github/workflows/deploy.yml` 会自动构建和部署

工作流会自动设置 `VITE_BASE` 为仓库名。如果部署到用户主页仓库（`<user>.github.io`），需要把 `VITE_BASE` 改成 `/`。

> GitHub Pages 在国内访问可能不稳定。代码可以放 GitHub，部署也可以换成 Cloudflare Pages、Vercel 或国内静态托管。

## 数据安全

- 上传的厂家 Excel 只在浏览器内存里处理
- 商品目录不包含成本价、库存、仓库位置
- 如果商品编号和规格也不能公开，需要使用私有后端或把目录改成用户本地加载
